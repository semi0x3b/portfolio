2024.07 ~ 현재

개발 기준·운영 문서와 사내 AI 도구 도입

코드·운영 질문이 특정 사람에게 몰리고 개발 기준이 리뷰어의 기억에 의존하던 업무 방식을 개선했습니다.

운영 문서 저장소 18곳 도입

팀원도 갱신하는 문서와 CI 기준

역할
팀 리드로 문서와 코드 검토 기준을 정리하고 CI·사내 도구에 적용했습니다. 주간 싱크업과 인턴 과제 배정·리뷰도 맡았습니다.
기술
Claude Code, Agent Skills, GitHub Actions, Python 정적 검사, Slack API, LLM

판단과 이유

같은 질문에 반복 답하거나 사람마다 다른 기준으로 검토하는 일을 줄이고, 팀원과 AI 도구가 같은 근거로 코드를 이해하게 하려 했습니다.

구현·개선

  • 용어·코드 구조·테스트와 운영 지식을 코드 옆 문서로 관리하고 CI·PR 단계에서 함께 갱신하게 했습니다. 코드 지도는 식별자와 파일 위치가 실제 코드에 있는지 검사했습니다.
  • 레이어 경계와 명명·파일 구조 규칙을 CI에서 검사하도록 만들고 기존 계층 위반 22건을 정리했습니다.
  • Slack 코드 설명 봇을 개선해 근거를 찾아 답하고 확인하지 못한 범위를 표시하게 했습니다. 도입 후보 도구는 비교 시험에서 정확도가 떨어지면 쓰지 않았습니다.
  • PR 본문 작성·권한 등록·배포·검증을 돕는 사내 스킬과 운영 에이전트를 배포했습니다. Agent Skills·Plugin System의 활용법을 전 직군 대상 사내 세미나에서 공유했습니다.
  • 사내 짧은 링크 발급 도구로 외부 유료 구독을 대체했습니다. 링크와 클릭 기록은 사내에서 관리하게 했습니다.

결과와 성과

  • 코드 옆 운영 문서가 회사 저장소 18곳에 도입됐고 관련 문서 변경의 3분의 2 이상을 팀원이 작성했습니다.
  • 개발 기준을 리뷰어만 확인하던 방식에서 CI가 검사하는 방식으로 옮겼습니다. 사내 스킬 24종과 인프라 운영 에이전트 9종을 배포하고 세미나에서 공유했습니다.
