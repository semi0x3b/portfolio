장애 감지·자동 복구와 AI 원인 분석

외부 API 무응답이 서비스 전체 정지로 번지고 헬스체크가 이를 감지하지 못한 장애를 계기로 감지·복구·분석을 함께 개선했습니다.

동시 요청 60건 모두 응답

외부 API 무응답을 넣은 개선 후 시험

역할
이벤트 루프 차단 원인 분석과 코드 수정, 헬스체크·알림 변경, 규칙·LLM 기반 분석 봇 개발을 맡았습니다.
기술
FastAPI, Kubernetes(OKE), Loki, Alertmanager, Slack API, LLM

판단과 이유

복구는 Kubernetes가 수행하고 AI는 근거 해석을 맡도록 역할을 나눴습니다. 봇의 분석 오류가 운영 변경으로 이어지지 않도록 변경 권한은 주지 않았습니다.

구현·개선

  • 응답 시간이 외부 API 타임아웃의 배수로 늘어나는 현상을 추적했습니다. await 없는 핸들러를 확인해 동기 I/O를 threadpool로 격리하고 사용자 경로의 타임아웃을 조정했습니다.
  • 이벤트 루프가 멈춰도 통과하는 tcpSocket 헬스체크를 HTTP 방식으로 바꿨습니다. 개발 환경에서 앱을 직접 멈춰 격리와 재시작을 확인한 뒤 적용했습니다.
  • 로그 알림에 원인 후보와 근거를 붙이는 봇을 만들었습니다. 규칙으로 먼저 신호를 분류하고 LLM이 해석하며 인용 문장이 실제 로그에 있는지 발송 전에 대조합니다.

결과와 성과

  • 개선 후 외부 API 무응답 상황에서 동시 요청 60건이 모두 응답했습니다. HTTP 헬스체크로 같은 정지 증상을 감지하고 자동 복구하게 됐습니다.
  • 과거 장애 2건의 재현 자료에서 기록된 원인을 찾았습니다. 2주치 알림 18건 중 9건은 LLM을 호출하지 않고 규칙으로 판정했습니다.
