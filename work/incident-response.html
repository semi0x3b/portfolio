장애 자동복구와 AI 원인분석 체계

서비스 25종 probe 전환, 장애 부검 봇

전체 정지에서 ;
60건 모두 응답으로 외부 API가 응답하지 않는 동안. 앞은 실제 장애(11분 정지), 뒤는 적용 뒤 동시 60요청 시험
기술
FastAPI, Kubernetes, Loki, Alertmanager, LLM
글과 코드
부검 봇 설계 글 log-autopsy 공개판

문제

;

외부 기관 API(HRD-Net)가 응답하지 않자 권한 서비스 전체가 11분 동안 멈췄습니다. 장애는 사용자 신고로 알았고, 그동안 K8s도 아무 조치를 하지 않았습니다.

한 일

;
  • 응답시간이 read timeout 30초의 배수로 쌓이는 분포를 보고, async def 핸들러가 동기 I/O를 실행하는데 워커가 하나라서 이벤트 루프 하나가 전체를 막는 구조라는 것을 찾았습니다. await가 없는 핸들러 94건을 AST로 골라 sync로 바꿔 threadpool에 격리했습니다.
  • tcpSocket liveness는 커널이 소켓 연결을 받아 주기 때문에 이벤트 루프가 멈춰도 통과합니다. 서비스 25종을 httpGet으로 바꾸고, 앱 프로세스를 직접 멈춰서 45초 안에 재시작되는 것을 확인했습니다.
  • 장애 분석 봇을 만들었습니다. 규칙이 신호를 찾고 LLM은 해석만 맡으며, 발송 전에 인용 문자열을 원본 로그와 기계로 대조해서 근거 없는 판정은 강등합니다. 봇에는 prod 변경 권한을 주지 않았고 복구는 K8s가 맡도록 나눴습니다.

결과

;
  • 외부 API가 멈춘 동안에도 동시 60 요청이 모두 응답했습니다(QueuePool timeout 0건).
  • 25종에 롤아웃한 뒤 probe 오탐으로 재시작한 경우는 0건입니다.
  • 과거 실제 장애 2건을 다시 돌리자 봇이 기록된 원인까지 찾아갔습니다. 뒤에 규칙 층을 앞에 두자 2주치 에러 알림 18건 중 9건은 LLM 호출 없이 판정이 끝났습니다.
